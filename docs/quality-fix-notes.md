## 原因と対応箇所

| 層 | 調査結果と対応 |
| --- | --- |
| 出力契約 | 既存の状態・候補件数・必須項目・参照形式で表現可能。変更不要 |
| 検証処理 | Schema・ReferenceValidatorは構造と参照の実在を検証する。既存IDでも文全体を支持するとは限らない。意味を単語の一致で判定する通常応答用フィルターは追加しない |
| プロンプト | 一般的な禁止事項はあったが、複数行の合成、log_statusの意味範囲、要約による断定、確認リスト後半への原因混入、案内の欠落が実際に発生。出力前の項目別点検と具体例を追加 |

## 回帰テストの境界

QualityRegressionTestとquality-regressions.jsonに、既存入力を使う9組の合成不適合例・修正例を追加。
実AIの生応答は転記していない。既存のcases.jsonとhuman_checksは変更していない。

- 内容例9件：行参照、入力項目参照、判断理由の断定、引き継ぎの断定、調査進捗の創作、DB確認、タイムゾーン欠落、窓口案内欠落、業務上の意味付け。
- 両応答がSchema・ID検証に通ることと、合成ケース専用の内容チェックで区別できることを確認する。
- 内容チェックは既知の合成文・既知の入力に限定した回帰検出。言い換え・否定・複雑な因果関係の意味を一般的に保証しない。通常の応答拒否には使用しない。
- 修正指示が実際の計数・生成リクエストに同じ形で組み込まれ、確認済み入力が維持されることを確認する。モデルが指示に従うことを証明するテストではない。
- 決定的な規則4件：情報不足・対象外の候補非空はSchemaで拒否し、存在しない候補への引き継ぎ参照はReferenceValidatorで拒否する。
- IDの存在、一意性、source_typeとの対応、未入力項目の参照禁止などは従来のテストとコード検証を継続する。

## 実AIで再確認する項目

修正後にA/B/Cを各3回、既存の固定入力で評価する。B/Cの取得状況は「未取得」に統一する。
異なる取得状況を試す場合は参考ケースとして分ける。

全ての事実について文章全体を参照先と照合し、判断理由・要約・引き継ぎにも未確認表現が保たれるかを確認する。
情報不足では確認事項の先頭だけでなく全件と不足情報を評価する。
発生日時・タイムゾーンと対象外時の窓口案内は、既存基準に従って意味で評価する。
単語の有無だけで合格にせず、部署の創作や変更操作の提案がないことも確認する。
生成品質の改善・安定性はこの手動評価が終わるまで未確認。
