# Specification

## 1. プロジェクト概要

### プロジェクト名

Incident Triage Assistant

### 概要

Webアプリケーションの運用保守において、障害発生時の一次切り分けをAIで支援するWebアプリケーション。

障害内容やログ情報を入力すると、AIが状況を整理し、原因候補・確認手順・不足している情報・エスカレーション時に必要な情報を提示する。

AIが障害を自動修正することを目的とせず、一次調査の標準化と効率化を目的とする。

---

## 2. 解決したい課題

障害発生時には、担当者によって以下のような問題が発生する。

- どこから確認すればよいか分からない
- ログのどの部分を確認すればよいか分からない
- 必要な情報が不足した状態でエンジニアへエスカレーションされる
- 担当者によって調査手順や品質にばらつきがある
- 過去の手順書やFAQを探すのに時間がかかる

本システムでは、AIを活用して一次切り分けの支援を行い、これらの問題を軽減する。

---

## 3. 想定ユーザー

### 主なユーザー

- 運用保守担当者
- ヘルプデスク担当者
- 一次切り分けを担当する非開発者
- Webアプリケーションを保守するエンジニア

### 想定利用シーン

Webアプリケーションで障害が発生し、担当者が原因調査を開始するとき。

例：

- 画面操作時にHTTP 500が発生した
- 商品登録処理に失敗した
- DB接続エラーが発生した
- 外部APIとの通信がタイムアウトした
- Java例外がログに出力された

---

## 4. 初期対象システム

初期PoCでは、以下のようなWebアプリケーションを想定する。

- Java
- Spring Boot
- RDBを利用する業務Webアプリケーション
- REST APIを利用するバックエンドシステム

初版ではWebアプリケーションの一次切り分けに対象を限定する。

---

## 5. 入力情報

ユーザーは以下の情報を入力できる。

### 必須

#### 発生事象

障害発生時の状況を文章で入力する。

例：

> 管理画面から商品を登録すると500エラーになります。

#### ログ

アプリケーションログやエラーログをテキストで入力する。
